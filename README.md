# Perfect Season 🏈

Perfect Season is a fantasy football draft game that runs entirely in one HTML
file. You are given a slot in a twelve-team PPR league, and eleven computer
teams draft around you off the real consensus board while you make eight picks
of your own. Your finished roster then plays a seventeen-week season against
the eleven rosters those teams just built, and the record you end up with earns
your team a label somewhere between Championship Threat and Taco. Every season
can be shared with a link that replays the whole thing for whoever opens it.

There is no backend, no database, no account system, and no build step. The
only thing the page loads from the network is its typefaces.

## Where the player data comes from

The board is the FantasyPros PPR redraft consensus, which aggregates rankings
from more than a hundred analysts. Each player carries his current team, his
real bye week, and his consensus rank, and the pool holds the top twenty-four
quarterbacks, thirty-six running backs, forty receivers, and sixteen tight
ends. Free agents are excluded, so a player who is unsigned or unlikely to play
never appears on the board.

Projected points per game come from FantasyPros PPR projections, applied by
position rank rather than by name. The four positions fall away from their top
scorer at very different rates, and that difference is the most interesting
decision in the draft: the second-best tight end outscores the twentieth-best
receiver by a wide margin even though the board prices the two of them only a
few picks apart. The computer teams draft the consensus board and never reason
about those curves, which is the opening you are meant to exploit.

## Refreshing the board

Rankings move constantly during the summer, so the pool is regenerated by a
script rather than maintained by hand. Running it from the repository root with
Node 18 or newer rewrites the player block in `index.html` from the latest
published rankings:

```bash
node update-adp.mjs
git add -A && git commit -m "refresh player pool" && git push
```

Use `node update-adp.mjs --check` to see what a refresh would change without
touching anything, and `--file` to apply a previously saved copy of the CSV.

The default source is the FantasyPros consensus because it is reachable from
essentially anywhere. If you would rather use ESPN's own average draft
position, which records the order players actually came off the board in ESPN
drafts instead of what analysts think, run `node update-adp.mjs --source espn`.
ESPN blocks a fair number of networks, so if that request fails you can save
the two responses yourself and hand them to the script:

```bash
curl -H 'X-Fantasy-Filter: {"players":{"limit":500,"sortDraftRanks":{"sortPriority":100,"sortAsc":true,"value":"PPR"}}}' \
  "https://lm-api-reads.fantasy.espn.com/apis/v3/games/ffl/seasons/2026/segments/0/leaguedefaults/3?view=kona_player_info" -o players.json
curl "https://lm-api-reads.fantasy.espn.com/apis/v3/games/ffl/seasons/2026/segments/0/leaguedefaults/3?view=proTeamSchedules_wl" -o schedule.json
node update-adp.mjs --espn-players players.json --espn-schedule schedule.json
```

A refresh also advances the share-link version, which expires every link
created before it. That is deliberate. A link replays a draft against the pool
it was created from, so an old link opening against a new board would show a
roster that no longer matches reality. Expired links open on the home screen
instead.

## How the share links work

Finishing a season enables a button that packs the entire result into the URL,
because nothing is ever stored on a server:

- `?s=` carries sixteen characters of base64url holding a version number, your
  draft slot, your eight picks, and the random seed the season ran on. Opening
  the link replays the draft and the season from those pieces, which reproduces
  the computer teams' picks, every weekly score, and the final record exactly.
- `&n=` optionally carries a display name of up to twenty characters so the
  page can title itself properly.

Anyone opening a link sees a read-only version of the result with the record,
the tier, the week-by-week ticker, the full season log, and the roster, plus a
button to start a draft of their own. A malformed or expired link simply opens
the home screen rather than failing.

## Running it locally

Opening `index.html` in a browser is enough to play. Some browsers restrict
clipboard access on `file://` pages, so if you want to test the copy buttons,
serve the directory instead with `python3 -m http.server` and visit
`http://localhost:8000`.

## Deploying it

A GitHub Actions workflow already publishes the site to a `gh-pages` branch on
every push, so the finished site is sitting in the repository waiting to be
served. Turning it on takes one visit to the repository settings: open
**Settings → Pages**, set the source to **Deploy from a branch**, choose
**gh-pages** with the root folder, and save. About a minute later the game is
live at `https://jerryvix.github.io/PerfectSeason/` and every future push
updates it automatically. GitHub reserves that switch for the repository
owner, which is why the workflow could not flip it by itself.

Vercel is an equally good home, and the project needs no configuration there
at all.
Sign in at [vercel.com](https://vercel.com) with GitHub, choose **Add New →
Project**, import this repository, leave every setting at its default, and
deploy. Afterwards any `git push` redeploys the site automatically within about
thirty seconds, which makes the refresh command above the entire update
procedure.

Netlify works the same way through **Add new site → Import an existing
project**. You can also drag the folder onto
[app.netlify.com/drop](https://app.netlify.com/drop), though that route has to
be repeated by hand after every change while the Git route does not.

## How the game is set up

Your lineup is one quarterback, two running backs, two receivers, one tight
end, and two flex spots that accept a back, a receiver, or a tight end. The
board only ever offers players who can still complete a legal lineup, which is
why a second quarterback stops appearing once you have taken one.

The season schedule plays each of the eleven opponents once and then six of
them a second time. Each player draws a score around his projection every week
and contributes nothing during his bye, so stacking byes into a single weekend
is a real mistake. Simulating thousands of drafts puts a roster built on the
scoring curves around eleven or twelve wins, a roster that simply follows the
consensus board around ten, and a careless one near two. A perfect seventeen
and zero happens well under one percent of the time.

Records earn a tier: seventeen wins is a Perfect Season, fifteen or more is a
Championship Threat, twelve is a Contender, nine is a Pretender, five is a
Basement Dweller, and anything below that is a Taco.
